# Shared data and storage

Everything a visitor enters stays in their own browser (`localStorage`). Nothing is sent anywhere. Four keys hold shared data, and My Profile (`my-profile.html`) shows and edits all of them in one place.

| Key | Written by | Read by | What it holds |
|---|---|---|---|
| `bl_diy_profile_v1` | Paid 01 (Business Profile), the Business Profile form on My Profile, and a pasted `BL1.` code on any toolkit | Every toolkit except RevOps 1–6, the strategy starters, the roadmap | The Business Profile (schema below) |
| `bl_diy_assess_v1` | The four strategy starters and the roadmap, each in its own section | The starters (to reuse each other's answers) and the roadmap | Starter answers and results, the roadmap goal and done marks |
| `bl_diy_progress_v1` | The shared tracking script on toolkit pages (generated by `tools/site_header.py`) | The roadmap, Your journey, My Profile | Which toolkits a visitor has worked on |
| `bl_diy_answers_v1` | The shared answers script on toolkit pages (`bl-answers-js`, generated by `tools/site_header.py`) | The same toolkit (to restore answers) and My Profile | Each toolkit's own answers, with question labels |
| `bl_hub_theme` | Hub, review page | Hub, review page | `light` or `dark` |

## Business Profile, `bl_diy_profile_v1` (unchanged)

```
{ v: 1, name, industry, model: 'b2b'|'b2c'|'both', offer: 'products'|'services'|'both',
  ecommerce: 'shopify'|'other'|'none', locations: 'none'|'one'|'multi',
  reach: 'local'|'regional'|'national'|'international', app: bool, crm: 'hubspot'|'other'|'none',
  website: bool, goal: 'leads'|'calls'|'sales'|'visits'|'installs'|'awareness', adBudget: number|null,
  ga4: 'yes'|'no'|'unsure', gtm: 'yes'|'no'|'unsure', gbp: 'yes'|'no'|'na' }
```

Rules: only Paid 01 writes it automatically, and only once the answers differ from the example. My Profile writes it when the visitor presses "Save my profile" (merging into the saved profile, so fields it doesn't show survive). Other pages write it only when the visitor pastes a code. No page may save example answers into it.

## Strategy starters and roadmap, `bl_diy_assess_v1` (new)

```
{ v: 1,
  situation: { v: 1, answers: { <signal>: value, data?: { <field>: number } }, result: { market, conf, limiting, axes, depth, lead, top, data? }, updated },
  gap:       { v: 1, answers: { <area>: 'usable'|'weak'|'missing'|'unknown'|'na', aud?: {...} }, result: { counts, top, gaps, aud? }, updated },
  brand:     { v: 1, answers: { ..., gtm?: { ch, j } }, edits: { <output>: text }, result: { positioning, promise, value, voices, gtm? }, updated },
  delight:   { v: 1, answers: {...}, result: { fixes, risk, strong, motions?, thin? }, updated },
  roadmap:   { v: 1, goal, done: { <actionId>: ISO date }, updated } }
```

Optional fields added Oct 22, 2026 (Coby's review). They are additive, so `v` stays 1 and older saves still load:
- `situation.answers.data`: the optional real numbers (`mk_volume`, `mk_trend`, `mk_comp`, `mk_ads`, `mk_size`, `mk_cust`, `mk_brand`, `bz_cac`, `bz_cac_prev`, `bz_value`, `bz_disc`, `bz_repeat`, `bz_ref`). `result.data` is how many were entered. The free-text `sell`, `pay` and `deliver` answers are no longer asked; older saves may still hold them, and the go-to-market starter still reads `sell` from them.
- `gap.answers.aud`: who buys and what drives them (`type`, `age`, `life`, `shop`, `size`, `role`, `where`, `source`, `drivers`, `trigger`, `decide`, `hesitate`, `words`). `result.aud` keeps `type`, `drivers`, `decide`, `whoKnown`, `driveKnown`.
- `brand.answers.gtm`: `ch` is `{ <channel>: { spend, work } }`, `j` is the customer-journey answers. `result.gtm` is `{ total, byStage, byMotion, channels, flags }`. The roadmap reads `flags`.
- `delight.answers` now also holds the Notice Different (`nd_*`) and Align to Genuine (`ag_*`) activities. `result.motions` is the level per motion and `result.thin` the thinnest one.

Rules:
- A starter writes only its own section, through `saveAssessPart()`.
- Answers are saved only after the visitor changes something (or when they were saved before). Example answers are never saved, even when a profile is loaded.
- The brand starter keeps visitor edits to its outputs in `edits` and never overwrites them on regenerate.

## Progress, `bl_diy_progress_v1` (new)

```
{ v: 1, kits: { "<series>-<nn>": { first, last, worked: true, headline, planTaken } } }
```

Written by the shared tracking script only on toolkit pages, only after a real (trusted) answer change, and never while the page shows example answers. `headline` is the page's result line, up to 180 characters. `planTaken` is set when the visitor copies or prints their own plan. The roadmap shows this as progress. Only the visitor's own "I've done this" mark counts as done.

## Toolkit answers, `bl_diy_answers_v1` (new, Oct 22, 2026)

```
{ v: 1, kits: { "<series>-<nn>": { v: 1, title, url, updated,
    fields: [ { k, type: 'radio'|'checkbox'|'value', label, value, text } ] } } }
```

Written by the shared answers script on every toolkit page except Paid 01 (its answers are the Business Profile).
- It saves (debounced, 700 ms) only after a real (trusted) input or change inside `#answers`, and never while the page shows example answers.
- Radios and checkboxes are saved by `name`; other inputs, selects and textareas by `id`. `label` comes from `aria-labelledby`, `label[for]` or the question's label element; `text` is the chosen option's label, for display on My Profile.
- On load it puts saved answers back, fires `input` and `change` so the result recalculates, and shows a "Welcome back" note linking to My Profile. The four strategy starters already restore themselves from `bl_diy_assess_v1`, so for them this key is display-only.
- "Go back to the example answers" on a toolkit removes that toolkit's entry.
- My Profile groups entries by series, shows each with its result headline (from `bl_diy_progress_v1`), and links "Edit in toolkit". "Remove these answers" deletes one entry.

## Versioning and migration

- Every key and every section carries `v`. Readers use data only when they understand its `v`.
- Writers never overwrite a key whose `v` is newer than they understand (`saveAssessPart` returns `false`; the progress writer stops).
- A breaking change gets a new key name (`bl_diy_assess_v2`, and so on). The new build reads the old key, migrates it, and writes the new key. It leaves the old key in place for one release, so a rollback still works.
- Adding optional fields is not a breaking change: readers must tolerate missing fields.

## Clearing data

- "Clear" on a profile strip removes the Business Profile for every toolkit.
- "Clear everything" on My Profile removes all four keys after an inline confirmation. My Profile can also export all four keys as one JSON file (`app: 'big-leap-diy-toolkits'`) and import that file on another browser.
- "Clear my roadmap from this browser" on the roadmap removes `bl_diy_assess_v1` and `bl_diy_progress_v1`, and keeps the Business Profile. It asks for confirmation first.
