# Shared data and storage

Everything a visitor enters stays in their own browser (`localStorage`). Nothing is sent anywhere. Three keys hold shared data; every toolkit page also keeps its own answers only in the page while it is open.

| Key | Written by | Read by | What it holds |
|---|---|---|---|
| `bl_diy_profile_v1` | Paid 01 (Business Profile) only, plus a pasted `BL1.` code on any toolkit | Every toolkit except RevOps 1–6, the strategy starters, the roadmap | The Business Profile (schema below) |
| `bl_diy_assess_v1` | The four strategy starters and the roadmap, each in its own section | The starters (to reuse each other's answers) and the roadmap | Starter answers and results, the roadmap goal and done marks |
| `bl_diy_progress_v1` | The shared tracking script on toolkit pages (generated by `tools/site_header.py`) | The roadmap | Which toolkits a visitor has worked on |
| `bl_hub_theme` | Hub, review page | Hub, review page | `light` or `dark` |

## Business Profile, `bl_diy_profile_v1` (unchanged)

```
{ v: 1, name, industry, model: 'b2b'|'b2c'|'both', offer: 'products'|'services'|'both',
  ecommerce: 'shopify'|'other'|'none', locations: 'none'|'one'|'multi',
  reach: 'local'|'regional'|'national'|'international', app: bool, crm: 'hubspot'|'other'|'none',
  website: bool, goal: 'leads'|'calls'|'sales'|'visits'|'installs'|'awareness', adBudget: number|null,
  ga4: 'yes'|'no'|'unsure', gtm: 'yes'|'no'|'unsure', gbp: 'yes'|'no'|'na' }
```

Rules: only Paid 01 writes it automatically, and only once the answers differ from the example. Other pages write it only when the visitor pastes a code. No page may save example answers into it.

## Strategy starters and roadmap, `bl_diy_assess_v1` (new)

```
{ v: 1,
  situation: { v: 1, answers: {...}, result: { market, conf, limiting, axes, depth, lead, top }, updated },
  gap:       { v: 1, answers: { <area>: 'usable'|'weak'|'missing'|'unknown'|'na' }, result: { counts, top, gaps }, updated },
  brand:     { v: 1, answers: {...}, edits: { <output>: text }, result: { positioning, promise, value, voices }, updated },
  delight:   { v: 1, answers: {...}, result: { fixes, risk, strong }, updated },
  roadmap:   { v: 1, goal, done: { <actionId>: ISO date }, updated } }
```

Rules:
- A starter writes only its own section, through `saveAssessPart()`.
- Answers are saved only after the visitor changes something (or when they were saved before). Example answers are never saved, even when a profile is loaded.
- The brand starter keeps visitor edits to its outputs in `edits` and never overwrites them on regenerate.

## Progress, `bl_diy_progress_v1` (new)

```
{ v: 1, kits: { "<series>-<nn>": { first, last, worked: true, headline, planTaken } } }
```

Written by the shared tracking script only on toolkit pages, only after a real (trusted) answer change, and never while the page shows example answers. `headline` is the page's result line, up to 180 characters. `planTaken` is set when the visitor copies or prints their own plan. The roadmap shows this as progress. Only the visitor's own "I've done this" mark counts as done.

## Versioning and migration

- Every key and every section carries `v`. Readers use data only when they understand its `v`.
- Writers never overwrite a key whose `v` is newer than they understand (`saveAssessPart` returns `false`; the progress writer stops).
- A breaking change gets a new key name (`bl_diy_assess_v2`, and so on). The new build reads the old key, migrates it, and writes the new key. It leaves the old key in place for one release, so a rollback still works.
- Adding optional fields is not a breaking change: readers must tolerate missing fields.

## Clearing data

- "Clear" on a profile strip removes the Business Profile for every toolkit.
- "Clear my roadmap from this browser" on the roadmap removes `bl_diy_assess_v1` and `bl_diy_progress_v1`, and keeps the Business Profile. It asks for confirmation first.
